# CAM 刀具半径补偿精确审计服务（纯后端）

面向精密加工工艺工程师的**纯后端** HTTP JSON 服务。对 CAM 输出的、由**闭合直线与圆弧图元**
按加工顺序连接而成的刀路，在应用左/右刀具半径补偿（G41/G42 语义）后，**精确**判定其能否安全
下发，并返回规范化的补偿图元与有符号面积。

* 不创建、不提供任何前端页面（FastAPI 的 Swagger/Redoc 浏览器界面已显式关闭）。
* **全程零浮点容差、零离散采样、不以“只检查相邻图元”代替全局判定。**
* 所有几何判定都是精确符号判定：直线-直线、直线-圆弧、圆弧-圆弧的精确相交与切触，
  含重叠区间（同线/同圆）。

---

## 1. 精确性是如何实现的

### 1.1 输入：以十进制原值建立几何

所有坐标与半径必须以 **十进制字符串** 提交（如 `"12.50"`、`"0.001"`、`"3e-2"`）。
裸 JSON 数字一律拒绝——因为 JSON 数字在常见技术栈中会先变成二进制浮点，服务无法再取得原值。
字符串用 `Decimal → Fraction` 精确转换，全程保持分子/分母整数。

### 1.2 多二次扩域上的精确代数数

交点、切触点可能含平方根（如线-圆、圆-圆相交）。每个请求构建一个独立的精确数域

```
Q(s0, s1, …, sm),   s_i² = D_i （D_i 为正元素）
```

* 元素以**稀疏的子集单项式有理基**表示：`x = Σ_S c_S · e_S`，
  `e_S = ∏_{i∈S} s_i`，`c_S ∈ Q`；乘法严格按
  `e_A·e_B = (∏_{i∈A∩B} D_i)·e_{A△B}` 闭合并记忆化。
* 符号判定**只使用域公理**：写 `x = a + b·s_m`，`a、b` 同号则 `x` 同号；
  异号则用精确范数 `a² − b²D_m` 的符号递归判定。不使用任何数值近似。
* 平方根可在域内精确表示时（如 `√(2−√3) = (√6−√2)/2`）自动识别，
  避免对同一实数重复扩塔；无法表示时才新增变量。候选根一律由 `y² == x` 精确验证。
* 有理整数的分解（用于模平方等价类）用确定性 Miller–Rabin（n < 2⁶⁴）+ Brent-Pollard ρ，
  因子都是精确因子；即便素性分类失误，也只会导致多余扩塔，**不可能产生错误几何结论**。

十进制 `decimal` 字段仅用于人工显示，使用高精度 Decimal 计算，**绝不参与任何判定**。

### 1.3 圆弧角度判定不用三角函数

点是否在圆弧上、两点在圆弧上的先后，完全由叉积/点积的符号决定
（`app/exact/arcs.py`），覆盖短弧、长弧（>180°）、半圆（对径端点）与整圆，
不存在“角度接近 π 的容差”。

## 2. 补偿构造（三种规定操作）

给定单位切矢 `t` 与补偿侧 `τ`（左 = +1，右 = −1）：

1. **直线平移**：沿其单位法向平移 `τ·tool`，方向不变。
2. **圆弧同心变径**：圆心与绕向不变；
   * 刀侧朝向圆心：补偿半径 `ρ − tool`。`ρ == tool` → **半径塌缩**；`ρ < tool` → **反向/过切**，
     均在仍是有理量时精确比较 `ρ²` 与 `tool²`；
   * 背向圆心：补偿半径 `ρ + tool`。
3. **相邻图元的规定连接**（在公共顶点处，`c = sign(cross(t_in, t_out))`）：
   * `c·τ < 0`（刀侧凸角）：插入以**原顶点为圆心、半径等于刀具半径**的规定圆角，
     连接两条支撑上的精确切触点；
   * `c·τ > 0`（刀侧凹角）：两条偏移支撑精确延长/修剪至其交点
     （线-线、线-圆、圆-圆）。对有两个数学交点的情形，凹连接点必须同时是
     incoming 支撑上“最后一个可达交点”和 outgoing 支撑上“第一个可达交点”，否则判过切；
   * `c == 0`：切向连续则共用同一切触点；切向反向则拒绝（方向反转）。

随后构造出的链必须满足：

* 逐段闭合（前段终点精确等于后段起点）；
* 是一条**方向不变的简单闭合曲线**：任意非相邻边界不得有额外交点（横交、孤立切触、
  区间重叠），相邻对只允许在公共接头接触；
* **绕向不变**：用单位切矢的精确旋转计数（复数旋转全部在域内表示，跨支割仅靠叉积符号判定）
  求总转数，合法简单闭合曲线必须为 ±1，且与编程轮廓一致；
* 返回规范化补偿图元与**有符号面积**（直线叉积项 + 圆弧扇形项的精确结构 + 显示十进制）。

候选对用**精确包围盒**与**精确空间网格**预过滤（网格单元索引由精确符号比较校正，
只能合并/重复候选，绝不漏判），使审计对数百上千图元仍可实用。

## 3. HTTP 接口（版本化）

基址：`http://<host>:<port>`，当前版本前缀 `/v1`。仅返回 JSON。

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET  | `/health`、`/v1/health` | 健康检查（容器 HEALTHCHECK 使用） |
| GET  | `/v1` | 版本信息 |
| POST | `/v1/audit` | 提交刀路并审计 |

### 3.1 请求

```json
{
  "tool_radius": "1.00",
  "side": "left",
  "decimal_places": 12,
  "contour": [
    {"type": "line", "start": ["0", "0"], "end": ["10", "0"]},
    {"type": "line", "start": ["10", "0"], "end": ["10", "10"]},
    {"type": "line", "start": ["10", "10"], "end": ["0", "10"]},
    {"type": "line", "start": ["0", "10"], "end": ["0", "0"]}
  ]
}
```

* `tool_radius`：正十进制字符串。
* `side`：`"left"` 或 `"right"`；也可在单个图元上用 `side` 覆盖（相邻图元补偿侧
  不一致会被拒绝）。
* `contour`：图元必须**首尾相接并闭合**（前一图元 end 精确等于后一图元 start）。
  * 直线：`start`、`end`（端点必须不同）。
  * 圆弧：另需 `center`、`sense`（`"ccw"`/`"cw"`）；可选 `"full": true` 表示整圆
    （此时 start 必须等于 end）。非整圆且 start==end 必须显式声明 `full`，避免歧义。
* 可选 `id`：图元在缺陷报告中使用的可读标识。
* `decimal_places`：显示十进制位数（0–48），不影响精确判定。

### 3.2 合法响应 `200`

`status: "safe"`，`compensated_contour.pieces` 为按加工顺序排列的规范化图元
（`line` / `offset_arc` / `join_fillet`），每段带来源图元或连接顶点编号；
含 `orientation`、`turning_number` 与 `signed_area`。

每个数值都是

```json
{
  "exact": {"sqrt": {"rational": [15, 1]}},
  "decimal": "3.872983346207",
  "sign": 1
}
```

`exact` 是**可复算**的嵌套表达式（叶子为 `{"rational":[分子,分母]}`，
节点为 `{"sqrt": …}`、`{"*":[…]}`、`{"sum":[…]}`、`{"+":[a,{"*":[b,{"sqrt":D}]}]}`），
下游可据此逐位复算；`decimal` 仅为显示。圆弧扫掠角以
`{cos, sin, angle: "atan2(sin, cos) + 2*pi*full_turns"}` 的精确结构给出（整圆/半圆有专门标记）。

### 3.3 缺陷响应

* `422 {"status":"rejected", …}`：输入本身不合法（非十进制、链不闭合、退化直线、
  缺圆心/绕向等）。
* `409 {"status":"unsafe", …}`：补偿后不可安全下发。`error.first_defect` 返回
  **按刀路位置确定的首个缺陷**：
  * `tool_path_position`：片索引 + 段内位置（start/interior/end）与全序键；
  * `source_entities`：来源图元（索引与 id）；
  * `exact_point`：可复算的精确交点/切触点；对区间接触给出精确 `interval`；
    对修剪反转给出两个精确 `start_trim/end_trim`（即“隔离区间”的精确边界）。

典型缺陷码：

| code | 含义 |
| ---- | ---- |
| `radius_collapse` | 补偿圆弧半径精确塌缩为零 |
| `radius_inversion` | 刀具半径大于内凹圆弧半径，补偿弧反向 |
| `trim_order_reversal` | 凹区刀具放不下，修剪点次序颠倒（方向被破坏） |
| `traversal_reversal` | 顶点处行进方向精确反转 |
| `join_intersection_missing` / `gouging_corner` | 凹连接支撑无可达的唯一交点（过切） |
| `self_intersection` | 非相邻边界横交 |
| `non_adjacent_contact` | 非相邻边界孤立切触（曲线捏合，非简单曲线） |
| `non_adjacent_overlap` / `adjacent_overlap` | 非相邻/相邻边界区间重叠 |
| `adjacent_extra_contact` | 相邻片在公共接头之外接触 |
| `winding_change` / `orientation_reversed` | 绕向改变 |
| `chain_not_closed`、`degenerate_line`、`arc_endpoint_radius_mismatch` 等 | 输入结构错误 |

## 4. 车间部署（Docker）

构建并启动：

```bash
docker compose up --build
# 自定义宿主机端口：
HOST_PORT=9090 docker compose up --build
```

* `Dockerfile`：`python:3.11-slim`，仅安装 ASGI 运行时（几何核只用标准库）；
  非 root 之外的默认设置；容器内监听 `APP_PORT`（默认 8080）。
* `docker-compose.yml`：宿主机端口由环境变量 `HOST_PORT` 配置（默认 8080），
  含 `restart: unless-stopped` 与健康检查。
* 容器自带 `HEALTHCHECK`，每 15 秒请求 `/health`。
* 可用环境变量：`APP_HOST`、`APP_PORT`、`APP_WORKERS`、`APP_LOG_LEVEL`。

无 Docker 时本地运行：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

## 5. 测试

```bash
pip install -r requirements-dev.txt
pytest -q
```

测试包括：

* 代数核：符号判定、范数、嵌套根式恒等式、逆元、无多余扩塔；
* 圆弧成员/排序谓词（短弧、长弧、整圆、半圆）；
* HTTP：健康检查、十进制强制、方/圆/D 形/胶囊等轮廓的四种绕向×补偿侧，
  精确面积与独立数值积分对账；
* 缺陷：半径塌缩/反向、窄槽修剪反转、蝴蝶结自交、非相邻切触捏合、方向反转尖点；
* 随机化属性测试（浮点仅存在于测试侧做独立校验）：闭合性、简单性、面积一致。

---

## 6. 范围与限制

* 支持图元：闭合直线与圆弧（含整圆）。不支持样条/椭圆等非圆曲线。
* 精确数域为多二次扩域，覆盖线/圆相交产生的全部平方根型交点；这是该类刀路所需的全部代数数。
* 素性分解在 n < 2⁶⁴ 时确定性严格；CAM 坐标派生整数实际远小于此。
